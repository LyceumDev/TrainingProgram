## What working with an assistant looks like in this work

Modernization means understanding an existing system well enough to change it safely: what it does, why, where the risks are, and what the new version must preserve. Much of that work is reading code and documents, tracing how one thing leads to another, and writing down what was found. An AI assistant can carry a great deal of it, and a person who does not write code can direct the whole effort, because the direction is about purpose, priority, and acceptance, not syntax.

The working model is the same as everywhere on this portal. What is distinctive here is the environment: the assistant needs a place where it can read the code and the documents, and where anything it produces is reviewed the way any other change to the system is reviewed.

## What you can do now

- Read the [six lessons](~/lessons/index.html). Lessons 2 and 4 matter most in this case: the project record is the memory of the modernization, and the authority levels are what keep an assistant's technical ability from becoming an unreviewed change.
- Use the [business-analysis recipes](~/cases/business-analysis.html). The analysis half of modernization, from problem statements to traced requirements to comparisons of options, uses exactly those recipes today, in an approved browser or document environment, or with the guide during the interim, without touching the repository.
- [Book a guided first session](~/support/request-a-guided-session.html) and bring the system you are responsible for. The guide can show you what analysis of it looks like and what a repository environment would add.

## Boundaries that already apply

- The assistant reads and proposes; changes to a system are reviewed by the people who review changes to that system. Capability is not authority.
- Credentials, keys, and connection strings never enter the conversation or the project record. If a repository holds them, that is a finding to report, not a convenience to use.
- Anything that touches production data is a consequential action and goes through the organization's normal approvals.
