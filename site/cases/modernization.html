Modernization work

Repository analysis, design, coding, review, documentation, and coordination with a development team, including work directed by a person who does not write code.

What working with an assistant looks like in this work

Modernization means understanding an existing system well enough to change it safely: what it does, why, where the risks are, and what the new version must preserve. Much of that work is reading code and documents, tracing how one thing leads to another, and writing down what was found. An AI assistant can carry a great deal of it, and a person who does not write code can direct the whole effort, because the direction is about purpose, priority, and acceptance, not syntax.

The working model is the same as everywhere on this portal. What is distinctive here is the environment: the assistant needs a place where it can read the code and the documents, and where anything it produces is reviewed the way any other change to the system is reviewed.

What you can do now

  • Read the six lessons. Lessons 2 and 4 matter most in this case: the project record is the memory of the modernization, and the authority levels are what keep an assistant’s technical ability from becoming an unreviewed change.
  • Use the business-analysis task guides. The analysis half of modernization, from problem statements to traced requirements to comparisons of options, uses exactly those guides today, in an approved browser or document environment, or with the guide during the interim, without touching the repository.
  • Book a guided first session and bring the system you are responsible for. The guide can show you what analysis of it looks like and what a repository environment would add.

What waits for the repository environment

The complete case, with its own task guides for repository analysis, code review, documentation, and coordination with a development team, is published when a repository and development workspace is approved for wider use. Working teams in the program already use one for development tasks; the assessment is about extending it beyond them.

Boundaries that already apply

  • The assistant reads and proposes; changes to a system are reviewed by the people who review changes to that system. Capability is not authority.
  • Credentials, keys, and connection strings never enter the conversation or the project record. If a repository holds them, that is a finding to report, not a convenience to use.
  • Anything that touches production data is a consequential action and goes through the organization’s normal approvals.
